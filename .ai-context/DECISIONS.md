# Architectural Decisions

## [DECISION-001] MCP-first delivery over file injection
- **Date:** 2026-01-15
- **Status:** Accepted
- **Decision:** Context is delivered via MCP tool results, not by writing to CLAUDE.md or the system-prompt prefix.
- **Reason:** CLAUDE.md sits in the cache prefix, so every task change forces a full prefix re-write at 1.25× input price; MCP results land in the conversation tail with no per-task prefix write (~$0.08–0.14/session saved on a 10K layer).
- **Alternatives considered:** Full context in CLAUDE.md (v0.1); pointer-only CLAUDE.md + sidecar file.

## [DECISION-002] `.ai-context/` as canonical directory (`.cram-ai-context/` legacy fallback)
- **Date:** 2026-02-01
- **Status:** Accepted
- **Decision:** New repos use `.ai-context/`; the old `.cram-ai-context/` path is still supported via fallback in `context_dir.py`.
- **Reason:** Shorter, tool-agnostic name — the context layer should read as a repo artifact, not a vendor directory.
- **Alternatives considered:** Keep `.cram-ai-context/`; rename via migration script.

## [DECISION-003] Task slot namespacing per `get_context()` call
- **Date:** 2026-02-10
- **Status:** Accepted
- **Decision:** Each `get_context("task")` writes to `.ai-context/tasks/<slug>.md`, not a shared `CURRENT_TASK.md`.
- **Reason:** Concurrent agents sharing one file clobber each other's task context; per-task slots remove contention without coordination.
- **Alternatives considered:** Shared CURRENT_TASK.md (caused clobbering); lock files; per-PID files.

## [DECISION-004] Cheap model for context generation, not the session model
- **Date:** 2026-01-20
- **Status:** Accepted
- **Decision:** ARCHITECTURE.md and SYMBOLS.md are generated by a cheap/fast model (Haiku or equivalent), not the session model.
- **Reason:** Runs on every `cram sync` (post-commit), so cost/latency must be negligible; the output is summary, not creative work.
- **Alternatives considered:** Same model as the session; static analysis only (no LLM).

## [DECISION-005] Output byte-cap protection by default
- **Date:** 2026-03-01
- **Status:** Accepted
- **Decision:** Shell commands run via cram context are byte-capped (`| head -c 6000`), injected as a rule into CURRENT_TASK.md.
- **Reason:** Unbounded output (a big `cat`, an unlimited `git log`) floods the window thousands of tokens at a time; the injected cap needs no per-session config.
- **Alternatives considered:** Self-limiting agents; MCP-layer truncation; token-counting middleware.

## [DECISION-006] Git-commit-count staleness score over mtime
- **Date:** 2026-03-15
- **Status:** Accepted
- **Decision:** Context health is measured as commits-since-last-sync, not wall-clock time since last file change.
- **Reason:** mtime is unreliable (`git pull` bumps it without a regen); commit count directly proxies how much the codebase changed since sync.
- **Alternatives considered:** mtime delta (fallback when git unavailable); line-diff percentage.

## [DECISION-007] Decisions need human review before becoming permanent record
- **Date:** 2026-04-01
- **Status:** Accepted
- **Decision:** Agent-proposed decisions (`propose_decision`) are written `[PENDING]` and only accepted once a human approves in `cram ui` or edits the file.
- **Reason:** Agents can mistake a local implementation choice for a project-wide decision; the trust boundary must sit with the owner.
- **Alternatives considered:** Auto-accept proposals; separate approval file; ignore agent write-back.

## [DECISION-008] litellm as the model abstraction layer
- **Date:** 2026-01-10
- **Status:** Accepted
- **Decision:** All model calls go through litellm's unified interface.
- **Reason:** cram must support OpenAI, Anthropic, Google, Ollama, and enterprise proxies; per-provider adapters aren't the core product, and litellm handles auth, retries, and the OpenAI-compatible wire format.
- **Alternatives considered:** Anthropic SDK only; httpx with manual routing; langchain.

## [DECISION-009] Textual for TUI — optional dependency
- **Date:** 2026-04-15
- **Status:** Accepted
- **Decision:** `cram ui` requires `pip install cram-ai[tui]` — Textual is not a default dependency.
- **Reason:** Textual adds ~15MB to the install. Most users will never use the TUI (they use the MCP path). Making it optional keeps the default install lightweight.
- **Alternatives considered:** Always install Textual; use curses directly; no TUI (CLI-only).

## [DECISION-010] ARCHITECTURE.md stays a shared, committed artifact
- **Date:** 2026-06-14
- **Status:** Accepted
- **Decision:** Keep `.ai-context/ARCHITECTURE.md` tracked and committed — do NOT gitignore it. To stop the per-commit churn, `cram sync` embeds a sha256 fingerprint of the repo structure in the file and skips the LLM rewrite when the structure is unchanged (#24).
- **Reason:** Gitignoring removes it for everyone and degrades context for teammates and fresh sessions (`get_context` reads it every call) — the context layer is meant to be shared. The churn was non-deterministic Haiku regen, not a reason to stop sharing; fixing the regen is the real fix. Trade-off: the skip is keyed on file-tree structure only, so pure content changes won't refresh ARCHITECTURE until the file set changes (DECISION-006 staleness was aligned to this in #33).
- **Alternatives considered:** Gitignore it (un-shares); deterministic regen via fixed model/seed (heavier, still re-runs the LLM); accept churn and discard manually (ongoing friction).

## [DECISION-011] Carried-output loop is advisory-tightening only; active truncation deferred
- **Date:** 2026-06-15
- **Status:** Accepted
- **Decision:** Carried-output loop is **advisory-tightening only** (Option A: detect → auto-tighten `[output]` caps → verify with `cram rig`). **Active runtime truncation** (Option B, a PostToolUse hook rewriting tool output) is **deferred** until audits show advisory caps are ignored.
- **Reason:** B would put cram in another tool's silent-failure path — dropping needed output corrupts a session invisibly, against cram's measured/advisory ethos. A is reversible and yields the evidence to judge if B is ever worth its risk.
